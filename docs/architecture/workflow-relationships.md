# Workflow relationships

How the workspace is built and how work flows through it. This replaces the earlier `agentic-workflow-relationships.jpg`. For the live map of which agent delegates to which, see the delegation map in `README.md` and `registry.md`, both generated by `npm run sync`.

## Build flow

Canonical sources are written once; the generator produces every managed platform file.

```mermaid
flowchart LR
  subgraph sources["Canonical sources (edit these)"]
    wf[workflow.yaml<br>domains]
    ag[agents/*.md]
    cm[commands/*.md]
    sk[.agents/skills/*]
    cx[context/*.md]
  end
  sync{{npm run sync}}
  check{{npm run check}}
  subgraph generated["Generated (never edit)"]
    oc[.opencode/agents<br>.opencode/commands]
    cl[.claude/agents<br>.claude/commands<br>.claude/skills]
    co[.codex/agents<br>Codex command skills]
    rg[registry.md<br>README map]
  end
  sources --> sync --> generated
  sources -.-> check
  generated -.-> check
```

## Work flow

An agent uses the creation workflow to extend the workspace; agents and commands use skills to do the work; skills produce artifacts that feed later work.

```mermaid
flowchart TB
  agent([Agent: Asurada or a domain lead])
  scaffold{{/scaffold-workflow<br>+ skill-creator, command-creator}}
  subagents[Subagents]
  commands{{Commands}}
  skills[Skills<br>installed or created]
  artifacts[(Artifacts<br>docs/&lt;domain&gt;/)]

  agent -- triggers --> scaffold
  scaffold -- creates --> subagents
  scaffold -- creates --> commands
  scaffold -- creates --> skills
  agent -- delegates --> subagents
  commands -- run as --> subagents
  commands -- use --> skills
  subagents -- use --> skills
  skills -- generate --> artifacts
  artifacts -- feed --> agent
```

## Rules the diagrams encode

- Every subagent has a caller (listed in some agent's `delegates`); every skill is used by an agent or command.
- Domain leads coordinate multi-piece work; single deliverables can go straight to a subagent.
- Time-sensitive Game Ako work gets a `gaming-trend-scout` brief before writing.
- Artifacts are saved only on request, under the domain folders in `workflow.yaml`, following `context/artifacts.md`.
