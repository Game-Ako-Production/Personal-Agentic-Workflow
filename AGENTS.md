# Repository guide for agents

This repository stores Arohbi's agent workflow configuration, not application source. Canonical sources are written once and a generator produces the platform-native files for OpenCode, Claude Code, and Codex.

## Start here

- `registry.md` maps every domain, agent, command, skill, and artifact folder. It is generated; read it to route work.
- `agents/asurada.md` is the front door persona. OpenCode (`opencode.json`) and Claude Code (`.claude/settings.json`) open sessions as Asurada; in Codex, ask for the `asurada` agent explicitly.

## Canonical sources (edit these)

| What | Where |
| --- | --- |
| Domains, front door, platform list | `workflow.yaml` |
| Agents and subagents (frontmatter metadata + persona body) | `agents/<name>.md` |
| Command workflows (frontmatter metadata + workflow body) | `commands/<name>.md` |
| Skills (Agent Skills format) | `.agents/skills/<name>/SKILL.md` |
| Shared context appended to agent prompts via `includes` | `context/*.md` |
| Blank templates for new entities and briefs | `templates/` |

## Generated files (never edit by hand)

`npm run sync` writes `registry.md`, `.opencode/agents/`, `.opencode/commands/`, `.claude/agents/`, `.claude/commands/`, `.claude/skills/` (mirror of first-party skills, because Claude Code does not read `.agents/skills/`), `.codex/agents/`, and Codex command wrappers at `.agents/skills/<command>/SKILL.md`. Generated files carry a `GENERATED by scripts/sync.mjs` notice. `npm run check` fails when anything is stale, edited by hand, or references a missing file.

After changing any canonical source:

```sh
npm install   # first time only
npm run sync
npm run check
```

Use `/scaffold-workflow` (canonical workflow: `commands/scaffold-workflow.md`) to add or change agents, skills, commands, or domains.

## Platform notes

- OpenCode discovers `.opencode/agents/`, `.opencode/commands/`, and skills in `.agents/skills/` and `.claude/skills/` (duplicates resolve to the same content).
- Claude Code discovers `.claude/agents/`, `.claude/commands/`, and `.claude/skills/`, and reads this `AGENTS.md` when no `CLAUDE.md` exists. Do not add a `CLAUDE.md` unless it imports `@AGENTS.md`.
- Codex discovers `.codex/agents/*.toml` and `.agents/skills/`. It has no project-scoped command folder, so commands reach Codex through a skill: either a generated wrapper (`codex: wrapper`) or an existing skill that routes to the workflow (`codex: <skill-name>`). Never create `.codex/commands/`.
- Gemini CLI (`.gemini/`) and GitHub Copilot (`.github/agents/`, `.github/prompts/`) are frozen: hand-maintained, not generated or validated, and may reference outdated paths. Leave them untouched unless Arohbi asks.

## Artifacts

Answer on screen by default. Saved outputs follow `context/artifacts.md` and live under `docs/` in the folder owned by each domain in `workflow.yaml`. `docs/archive/briefs/` holds historical workflow briefs for reference only; they are not requirements.

## Dependencies

The root `package.json` provides the generator (`yaml` is its only dependency). The `.opencode/` package holds the OpenCode plugin dependency; run `npm install` there only when needed.
